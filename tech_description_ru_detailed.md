# Технологии и библиотеки в RAG-системе

## data_processing.py

### Основные библиотеки

#### langchain
**Описание**: LangChain — современный фреймворк для разработки приложений с использованием языковых моделей (LLM). Он предоставляет набор абстракций и инструментов, которые значительно упрощают создание сложных приложений на основе LLM. LangChain позволяет разработчикам фокусироваться на бизнес-логике, а не на технических деталях интеграции с различными моделями и источниками данных.

**Архитектура LangChain**:
- **Chains**: Последовательности операций, которые обрабатывают входные данные и генерируют выходные
- **Agents**: Компоненты, принимающие решения о следующем шаге в зависимости от контекста
- **Memory**: Механизмы для сохранения контекста между вызовами
- **Callbacks**: Система для отслеживания и мониторинга выполнения

**Применение в проекте**: 
- Загрузка документов из различных источников (PDF, HTML, DOCX, TXT)
- Разбиение документов на семантически связные фрагменты оптимального размера
- Создание и управление векторными представлениями документов
- Организация процесса извлечения информации (retrieval)
- Структурирование запросов к языковым моделям
- Интеграция с Qdrant для хранения векторных представлений

#### langchain_community
**Описание**: Это подмодуль фреймворка LangChain, который содержит интеграции с внешними сервисами, базами данных и моделями, поддерживаемыми сообществом. Данный модуль позволяет быстро подключать различные источники данных и инструменты без необходимости писать собственные адаптеры.

**Применение в проекте**:
- `DirectoryLoader` — загрузчик, который рекурсивно обходит указанную директорию и находит все документы заданных форматов. В нашем проекте используется для первичной обработки корпуса документов.
- `UnstructuredHTMLLoader` — специализированный загрузчик для HTML-документов, который извлекает текстовое содержимое, игнорируя HTML-теги и скрипты.
- `PyPDFLoader` — загрузчик для PDF-документов, который обрабатывает текст, таблицы и метаданные из PDF-файлов. Поддерживает многостраничные документы с сохранением информации о номере страницы в метаданных.
- `UnstructuredWordDocumentLoader` — загрузчик для документов Microsoft Word, извлекающий форматированный текст и структуру документа.
- `TextLoader` — базовый загрузчик для простых текстовых файлов с поддержкой различных кодировок.
- `Qdrant` — класс-обертка для интеграции с векторной базой данных Qdrant, предоставляющий методы для добавления, поиска и управления векторными представлениями документов.

#### langchain_core
**Описание**: Ядро фреймворка LangChain, содержащее базовые абстракции, интерфейсы и типы данных. Этот модуль определяет основные концепции, используемые во всех остальных компонентах LangChain.

**Применение в проекте**:
- `Document` — базовый класс для представления документов, содержащий текст (page_content) и метаданные (metadata). Все загрузчики документов преобразуют исходные файлы в объекты этого класса для унифицированной обработки.
- `Embeddings` — абстрактный интерфейс для моделей, создающих векторные представления текста. В нашем проекте реализованы собственные классы, соответствующие этому интерфейсу: `RoSBERTaEmbeddings` и `SimpleEmbeddings`.

#### langchain_text_splitters
**Описание**: Специализированный модуль LangChain для разбиения длинных текстов на меньшие фрагменты (чанки). Это критически важный компонент для RAG-систем, так как большинство языковых моделей имеют ограничение на длину контекста.

**Принципы работы**:
- Разбиение текста на фрагменты оптимального размера для обработки LLM
- Сохранение смысловой целостности фрагментов
- Контроль за перекрытием фрагментов для обеспечения непрерывности контекста

**Применение в проекте**: 
- `RecursiveCharacterTextSplitter` — интеллектуальный разделитель текста, который пытается сохранить смысловые границы, разбивая текст по абзацам, предложениям и другим естественным разделителям. В проекте используется для создания чанков размером 1000-1500 токенов с перекрытием в 150 токенов, что обеспечивает оптимальный баланс между точностью поиска и эффективностью.

#### langchain.retrievers
**Описание**: Модуль, предоставляющий различные алгоритмы и стратегии для извлечения релевантной информации из базы знаний.

**Типы ретриверов**:
- Векторные ретриверы (поиск по семантической близости)
- Статистические ретриверы (например, BM25, основанный на частоте слов)
- Гибридные ретриверы (комбинирующие несколько подходов)
- Контекстные компрессоры (фильтрующие и переупорядочивающие результаты)

**Применение в проекте**:
- `BM25Retriever` — реализация алгоритма Best Matching 25, статистического метода для оценки релевантности документов запросу на основе частоты терминов. Обеспечивает поиск по ключевым словам, дополняя семантический поиск.
- `EnsembleRetriever` — ретривер, который комбинирует результаты нескольких ретриверов, используя различные стратегии (перекрестная проверка, взвешивание). В нашем проекте объединяет результаты векторного поиска (по семантической близости) и BM25 (по ключевым словам).
- `DocumentCompressorPipeline` и `ContextualCompressionRetriever` — компоненты для дополнительной фильтрации и ранжирования найденных документов на основе контекста запроса.

#### langsmith
**Описание**: LangSmith — платформа для отладки, тестирования, мониторинга и улучшения LLM-приложений. Она позволяет отслеживать каждый шаг выполнения RAG-процесса, измерять производительность и выявлять проблемные места.

**Ключевые возможности**:
- Запись и визуализация цепочек вызовов между компонентами
- Мониторинг времени выполнения и использования ресурсов
- Сбор статистики для оптимизации системы
- Создание тестовых наборов для проверки качества ответов

**Применение в проекте**:
- `traceable` — декоратор для функций, который автоматически записывает информацию о вызовах, параметрах и результатах в LangSmith
- `trace` — контекстный менеджер для отслеживания выполнения блоков кода
- Создание иерархического дерева трассировки для анализа работы системы
- Важно: в контексте работы с LangGraph используется только внутри функций через `with trace(name="function_name"):` для обеспечения совместимости

#### Qdrant
**Описание**: Высокопроизводительная векторная база данных с открытым исходным кодом, специально оптимизированная для работы с эмбеддингами и векторными представлениями. Поддерживает различные алгоритмы приближенного поиска ближайших соседей (ANN) для быстрого поиска по миллионам векторов.

**Архитектурные особенности**:
- Встроенные фильтры для метаданных (фильтрация по полям payload)
- Несколько алгоритмов индексации векторов (HNSW, IVFPQ)
- Высокая производительность и масштабируемость
- API для локального и облачного развертывания

**Применение в проекте**:
- `QdrantClient` — клиент для взаимодействия с Qdrant API
- Хранение векторных представлений документов в коллекции "documents"
- Хранение метаданных документов вместе с векторами (payload)
- Гибкая фильтрация и поиск по векторам и метаданным
- Поддержка двух форматов документов:
  - с полем `text` для основного содержимого
  - с полем `page_content` и вложенным словарем `metadata`

#### numpy
**Описание**: Фундаментальная библиотека для научных вычислений в Python, обеспечивающая поддержку многомерных массивов и математических функций.

**Применение в проекте**: 
- Обработка и манипуляция с векторами эмбеддингов
- Нормализация векторов
- Преобразование разреженных матриц в плотные векторы
- Дополнение или обрезка векторов для обеспечения фиксированной размерности (1024)
- Оптимизация операций с большими наборами векторов

#### SimpleEmbeddings
**Описание**: Кастомный класс для создания эмбеддингов на основе TF-IDF (Term Frequency-Inverse Document Frequency). TF-IDF — статистическая мера, оценивающая важность слова в контексте документа с учетом частоты встречаемости в корпусе.

**Принцип работы**:
1. Создание словаря из корпуса документов
2. Подсчет частоты встречаемости слов в каждом документе
3. Вычисление обратной частоты документа для каждого слова
4. Формирование разреженных векторов
5. Преобразование в плотные векторы фиксированной размерности

**Применение в проекте**:
- Создание легковесных векторных представлений текста на основе TF-IDF
- Реализация интерфейса `Embeddings` из LangChain для совместимости
- Автоматическое добавление нулей для векторов меньше 1024 измерений
- Обрезка векторов, превышающих 1024 измерения
- Обеспечение совместимости с ожидаемой размерностью векторов в Qdrant

#### RoSBERTaEmbeddings
**Описание**: Кастомная обертка для модели RoSBERTa — версии BERT, специально обученной на русскоязычных текстах. Модель создает высококачественные контекстно-зависимые векторные представления текста.

**Особенности**:
- Понимание русского языка с учетом морфологии и синтаксиса
- Двунаправленное кодирование контекста (bidirectional encoding)
- Создание семантически богатых векторных представлений
- Совместимость с интерфейсом `Embeddings` из LangChain

**Применение в проекте**: 
- Создание высококачественных векторных представлений русскоязычных текстов
- Основной метод векторизации для семантического поиска
- Интеграция с Hugging Face через SentenceTransformer
- Обеспечение более точного поиска по смыслу запроса, а не только по ключевым словам

## rag_app.py

### Основные библиотеки

#### gradio
**Описание**: Фреймворк для быстрого создания веб-интерфейсов для моделей машинного обучения и искусственного интеллекта. Gradio позволяет легко демонстрировать ML-модели через интерактивные интерфейсы без необходимости разработки фронтенда с нуля.

**Применение в проекте**:

#### langchain_community.llms
**Описание**: Модуль с интеграциями различных языковых моделей, позволяющий работать с локальными и облачными LLM через унифицированный интерфейс.

**Поддерживаемые типы моделей**:
- Локальные модели различных форматов (GGUF, GGML, PyTorch)

**Применение в проекте**:

- Оптимизация производительности через контроль количества потоков и использования памяти
- Локальное выполнение инференса без отправки данных во внешние сервисы

#### langgraph
**Описание**: Библиотека для создания направленных ациклических графов (DAG) для оркестрации сложных процессов с использованием LLM. LangGraph позволяет определять многошаговые рабочие процессы с условными переходами и состояниями.

**Ключевые концепции**:
- **Nodes (узлы)**: Функции, выполняющие определенные задачи в графе
- **Edges (ребра)**: Связи между узлами, определяющие порядок выполнения
- **State (состояние)**: Данные, передаваемые между узлами
- **Conditional routing (условная маршрутизация)**: Динамическое определение следующего шага

**Применение в проекте**:
- `StateGraph` — для создания структурированного рабочего процесса RAG с четко определенными шагами:
  1. Извлечение документов по запросу пользователя
  2. Подготовка контекста из найденных документов
  3. Генерация ответа на основе контекста и запроса
  4. Формирование итогового ответа с источниками
- `MemorySaver` — для сохранения состояния между запросами и поддержки истории взаимодействия
- Определение типизированного состояния с помощью `TypedDict` для обеспечения типобезопасности
- Реализация контрольных точек для возможности возврата к предыдущим состояниям

#### langchain.schema
**Описание**: Модуль, определяющий базовые классы и абстракции для работы с LangChain. Включает интерфейсы для запуска моделей, форматирования промптов и парсинга выходных данных.

**Ключевые компоненты**:
- Runnable: Базовый интерфейс для компонентов, которые могут обрабатывать входные данные
- OutputParser: Интерфейс для преобразования вывода моделей в структурированные данные
- PromptTemplate: Шаблоны для формирования запросов к LLM

**Применение в проекте**:
- `RunnableConfig` — для конфигурации запуска моделей и цепочек
- `RunnableLambda` — для создания функциональных преобразований в цепочках
- `StrOutputParser` — для преобразования вывода модели в строковый формат
- Определение собственных цепочек преобразований для обработки запросов и ответов

#### langchain.retrievers
**Описание**: Модули для извлечения релевантных документов из хранилища, обеспечивающие различные стратегии поиска и ранжирования.

**Типы ретриверов**:
- Векторные ретриверы: поиск по семантическому сходству
- Статистические ретриверы: поиск по частоте и значимости слов
- Гибридные ретриверы: комбинация нескольких стратегий
- Контекстные компрессоры: дополнительная фильтрация и переранжирование

**Применение в проекте**:
- `BM25Retriever` — для поиска документов на основе статистического алгоритма BM25 (улучшенная версия TF-IDF)
- `EnsembleRetriever` — для комбинирования результатов векторного и BM25 поиска с взвешиванием результатов
- Реализация кастомной логики обработки документов с различными форматами полей
- Механизмы резервного поиска для обеспечения отказоустойчивости

#### langsmith
**Описание**: Платформа для мониторинга, отладки и улучшения LLM-приложений, обеспечивающая подробную трассировку выполнения и агрегацию метрик.

**Основные функции**:
- Трассировка выполнения цепочек и агентов
- Визуализация промежуточных результатов
- Мониторинг производительности
- Создание тестовых наборов для оценки качества

**Применение в проекте**:
- `Client` — для взаимодействия с API LangSmith

- Важно: для совместимости с LangGraph трассировка реализована через контекстные менеджеры `with trace(name="function_name"):` вместо декораторов `@trace`
- Сбор аналитики о времени выполнения каждого этапа RAG-процесса и качестве результатов

#### HybridSearch
**Описание**: Кастомный класс для реализации гибридного поиска, объединяющего семантический (векторный) и лексический (BM25) подходы к поиску информации.

**Принцип работы**:
1. Параллельный запуск векторного и BM25 поиска
2. Ранжирование результатов с учетом обоих подходов
3. Объединение результатов с удалением дубликатов
4. Применение дополнительных фильтров и ограничений

**Применение в проекте**:
- Создание комбинированного ретривера на основе `EnsembleRetriever`
- Адаптация к различным форматам документов (поддержка полей `text` и `page_content`)
- Обработка метаданных и управление количеством возвращаемых результатов
- Реализация механизма отката к прямому поиску в Qdrant при сбоях
- Подробное логирование для диагностики проблем с поиском

#### RAGAssistant
**Описание**: Основной класс, реализующий RAG-систему с использованием LangGraph. Организует взаимодействие между компонентами и управляет рабочим процессом.

**Ключевые компоненты**:
- Граф рабочего процесса (workflow graph)
- Обработчики состояний (state handlers)
- Система контрольных точек (checkpoints)
- Логика обработки истории диалога

**Применение в проекте**:
- Создание и управление графом рабочего процесса через `_create_rag_graph`
- Определение функций для каждого узла графа:
  - `retrieve_documents`: поиск релевантных документов
  - `generate_answer`: генерация ответа на основе документов и запроса
- Обработка пользовательских запросов через метод `answer_query`
- Формирование структурированных ответов с цитированием источников

#### LangChainAssistant
**Описание**: Класс для работы с языковой моделью через LangChain, обеспечивающий загрузку модели, форматирование запросов и обработку ответов.

**Основные функции**:
- Инициализация и настройка модели
- Форматирование истории диалога
- Подготовка системных промптов
- Обработка генерируемых ответов

**Применение в проекте**:
- Загрузка и инициализация локальной модели через `LlamaCpp`
- Формирование промптов с включением контекста из найденных документов
- Обработка многоязычных запросов и ответов
- Оптимизация параметров генерации (температура, длина ответа)
- Логирование процесса генерации и обработка исключений

### Особенности реализации и ключевые улучшения

#### 1. Поддержка различных форматов документов
**Проблема**: В Qdrant хранились документы с разной структурой: одни использовали поле `text` для основного содержимого, другие — поле `page_content` с вложенным словарем `metadata`.

**Решение**:
- Реализована гибкая логика определения формата документов при загрузке из Qdrant
- Добавлена поддержка обоих форматов в методе `_convert_qdrant_to_document`
- Внедрена система проверки и извлечения нужных полей из payload
- Реализовано корректное преобразование между различными форматами для обеспечения совместимости
- Добавлено подробное логирование для отладки проблем с форматами документов

#### 2. Трассировка с LangSmith
**Проблема**: Использование декораторов `@trace` на функциях, передаваемых в LangGraph, вызывало ошибку `'trace' object is not callable`, так как LangGraph ожидает функции, а не объекты трассировки.

**Решение**:
- Удалены декораторы `@trace` со всех функций, используемых в узлах LangGraph
- Внедрены контекстные менеджеры `with trace(name="function_name"):` внутри этих функций
- Обеспечена корректная обработка конфигурации RunnableConfig в методе `generate_response`
- Добавлены комментарии, объясняющие правильный подход к трассировке
- Создана четкая структура трассировки для всего процесса RAG

#### 3. Обработка размерности векторов
**Проблема**: TF-IDF векторизатор с параметром max_features=1024 не всегда создавал векторы размерности ровно 1024, что приводило к ошибкам при работе с Qdrant, который ожидает векторы фиксированной размерности.

**Решение**:
- Реализована автоматическая нормализация размерности векторов в методе `encode` класса `SimpleEmbeddings`
- Добавлено дополнение нулями для векторов с размерностью меньше 1024
- Внедрено усечение для векторов с размерностью больше 1024
- Улучшена обработка как одиночных векторов, так и батчей
- Добавлено логирование размерностей для диагностики

#### 4. Гибридный поиск
**Описание**: Система использует комбинацию семантического (векторного) и лексического (BM25) поиска для повышения точности и полноты результатов.

**Особенности реализации**:
- `EnsembleRetriever` объединяет результаты обоих типов поиска с настраиваемыми весами
- Добавлен механизм резервного поиска (fallback) через прямое обращение к Qdrant в случае сбоя LangChain ретривера
- Реализована фильтрация дубликатов в результатах поиска
- Добавлена детальная диагностика с выводом ключей и содержимого payload
- Улучшены методы преобразования между различными форматами документов для обеспечения максимальной совместимости
